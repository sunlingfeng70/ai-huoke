# 取数层以子进程方式复用，不导入

新工具通过**子进程**调用 `xhs-new-search` 技能里的 `xhs_new_search.py`，读取它落地的 `*_result.md` 与 `*_comments_*.json` 文件来获得笔记与评论，不把它当模块导入，也不复刻它的搜索与评论逻辑。

不导入是因为该脚本第 65 行的 `_bootstrap()` 是**模块级调用**，不在 `if __name__ == "__main__"` 保护之下。当前解释器若没有 `xhshow`，它会创建 venv、pip 安装依赖，然后用 `os.execv` **把调用方进程整个替换掉**，并把调用方的 `sys.argv` 交给 venv 里的 python 重新执行。这不是导入失败，而是导入会劫持并重启调用方——在 pytest 里会把测试进程自己 exec 掉。

也没有选择复刻那约 150 行搜索与评论代码（含 `xhshow` 签名逻辑）。虽然接口会更干净、可直接单测，但小红书的逆向接口是会变的，复刻等于让最易腐坏的部分存在两份副本。ADR-0004 选 CLI 的理由本就是复用已验证的形态、「直接接上比重写省事」，复刻与之相悖。

代价是靠文件与 stdout 交接：评论 JSON 按笔记分文件，调用方需自己汇总；且 `-c` 参数存在交互模式，必须始终传 `all` 或显式编号，否则子进程会停下等待输入。附带好处是这些 JSON 自带 `note_id` 与笔记标题，天然满足 ADR-0003 要求的归因留档。

`_bootstrap()` 的 `execv` 行为不去修改——那是另一个技能的文件，`xhs-new-search` 自身的用法依赖它，而从子进程调用时它的行为完全正确。
