# 命令行脚本 + Markdown 输出 + SQLite 存状态

交付形态定为命令行 Python 脚本：跑一条命令，输出一份按意向档排序的 Markdown 名单，跨批次状态存在单个 SQLite 文件里。不做 Web 界面，也不做成 opencode skill。

选命令行是为了复用已验证的形态——`xhs-new-search` 已经证明「命令行 + Markdown 输出 + 首次运行自动建 venv」这套在本机跑得通，而它本身就是本项目的取数层，直接接上比重写省事。Web 界面推迟到实际用过两周、知道哪里别扭之后再决定，否则是在没有线索的情况下猜界面需求。做成 skill 则不合适：技能形态适合一次性任务，而本项目需要长期保存排除名单和已触达记录。

选 SQLite 而非 JSON 文件，是因为每批采集都要查「这个评论者是否已被排除/已触达」，JSON 到几千条后全量读写会难受；而 SQLite 属 Python 标准库，零额外依赖，与现有脚本的零依赖风格一致。
