# 人工标注入口是手写的排除名单文件

人工把某位评论者标为「排除」的方式是：在名单里复制他的**用户ID**，粘进仓库里一个纯文本排除名单文件（一行一个用户ID）。脚本每次运行时读取该文件并同步进 SQLite——文件是人写的入口，SQLite 是系统读的状态。因此产出的 Markdown 名单必须为每条线索显式打印用户ID，否则人工无从复制。

选纯文本文件而非 `exclude <用户ID>` 子命令，是因为标注的物理动作就是「读名单时顺手记下几个ID」，纯文本是唯一不打断阅读节奏的载体。子命令每标一人要敲一次终端，这点摩擦足以让人干脆不标；而 ADR-0005 已经把排除档的准确性全部押在人工标注上，标注一旦不做，那个决策就失去唯一的纠错通道。也考虑过在 Markdown 名单里打勾回填，但名单是每批重新生成的产物，上一批打的勾会随文件名变化而丢失，除非让产出与状态挤进同一份文件。

以用户ID而非昵称为准，因为 `fetch_comments` 稳定返回用户ID，而昵称随时可改。
