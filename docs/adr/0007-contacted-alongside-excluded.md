# 已触达与排除并列，共用文件机制但语义不同

人工触达过某位评论者后，把他的用户ID连同日期写进一份**已触达名单**文件，格式与排除名单相同（ADR-0006）。产出的 Markdown 名单把已触达的评论者单独列成一节，显示「X 天前已触达」，不与未触达的线索混排。

之所以现在就做而不推迟到线索变多，是因为成本几乎为零——读取逻辑与排除名单完全一样——而漏做的代价是真实的：重复私信同一个陌生人在小红书是骚扰信号，而 ADR-0001 已经把这个账号的存续定为不可赌的东西。靠记忆认人在几十条线索时可行，到几百条时会出错，出错的方向恰好是风险最高的那个。

已触达与排除的关键区别是**时效性**：排除永久生效，已触达只是一个带日期的事实。系统只记录日期并把天数显示出来，**不定「多少天后可以再试」的规则**——那等于在还没触达过一个人的情况下凭空猜一个数字，与 ADR-0003 放弃关键词自扩展是同一类问题：没有回流信号就别编规则。要不要再试由人看着天数自己判断。
